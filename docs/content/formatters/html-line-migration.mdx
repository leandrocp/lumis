HTML formatters now emit `<span class="l-line" data-line="N">` instead of
`<div>`. Each span holds only its content; a `\n` text node separates consecutive
lines, with nothing after the last span. This is valid phrasing content inside
`<pre><code>` and avoids doubled newlines in `innerText`.

```html
<pre class="lumis"><code class="language-plaintext" translate="no" tabindex="0"><span class="l-line" data-line="1">first</span>
<span class="l-line" data-line="2">second</span></code></pre>
```

Classes, `data-line`, highlight classes and gutter elements are unchanged.
A final LF or CRLF terminates the last line rather than adding an empty numbered
line: `"a\n"` renders one line, `"a\n\n"` renders two, and an empty input still
renders one empty line. HTML separators are always LF; terminal and BBCode output
retain their source terminators.

## Custom CSS

Update the theme stylesheet together with the formatter. The bundled stylesheets,
and the CSS that `CssBuilder`, `build_css` and `buildCss` generate, end with this
block:

```css
@layer lumis {
  pre.lumis > code {
    display: block;
    width: fit-content;
    min-width: 100%;
    overflow-wrap: anywhere;
  }
  pre.lumis > code > span.l-line {
    display: inline-block;
    width: 100%;
    min-height: 1lh;
    vertical-align: top;
  }
  .l-line-number {
    -webkit-user-select: none;
    user-select: none;
  }
}
```

`<code>` grows to its longest line, so a highlighted line covers the whole
scrolled width, and a block wrapped with `white-space: pre-wrap` still wraps at
its container. `min-height` keeps an empty line one row tall, and
`vertical-align: top` stops it from sitting on the baseline and stretching the
row. The line rule only matches `span.l-line`, so the `<div>` lines older Lumis
versions wrote keep their block layout.

The block lives in the `lumis` cascade layer. Rules outside a layer beat layered
rules regardless of specificity or load order, so your own CSS wins. If your CSS
is in layers too, as with Tailwind v4, declare `lumis` before them; the
[Tailwind CSS recipe](/recipes/tailwind-css) shows the one line it takes.

If your stylesheet targets lines:

- Replace selectors such as `div.l-line` with `.l-line`.
- Drop `display: block` from line rules. A block line plus the newline after it
  renders an extra blank row. `code { display: grid }` is no way around it
  either: some engines then leave empty lines out of copied text.
- Add `box-sizing: border-box` when a line has horizontal padding or a border,
  so it still fits in `width: 100%`.

HTML Inline and HTML Multi-Themes have no stylesheet, so they write the same
layout as inline styles: on highlighted and empty lines, on `<code>` when lines
are highlighted, and `user-select: none` on line numbers. `style: nil` (`null` in
JavaScript) drops the highlight colors and keeps the layout.

## Custom formatters

`render_lines_from_events` / `renderLinesFromEvents` returns content-only lines.
Remove any terminator stripping. `wrap_line` / `wrapLine` wraps the content in a
span but adds no newline, so join its results explicitly. Apply the CSS above
when laying out these custom line wrappers.

A per-line table, diff view or stream can use the returned content directly,
without adding separators.

## Copy buttons

Keep the original source for exact copies. Browsers normalize CRLF, the formatter
omits the final terminator, and `innerText` / `textContent` include gutter text.
`user-select: none` excludes numbers from selection copy, not from those DOM
properties. Chromium also trims trailing blank rows containing only unselectable
gutters from a selection. Copying the source avoids all of these differences.

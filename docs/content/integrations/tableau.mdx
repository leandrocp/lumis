`Tableau` already uses `MDEx` for Markdown by default. That makes Lumis a built-in integration point rather than a custom post-processing step.

The hook you want is Tableau's `config :tableau, :config, markdown: [mdex: ...]` configuration. Pass Lumis formatter options through MDEx's `syntax_highlight` setting.

## Add dependencies

```elixir
def deps do
  [
    {:tableau, "~> 0.30"},
    {:lumis, "~> 0.9"}
  ]
end
```

No `lumis_wasm_*` packages in that list, and no `:mdex_native` configuration.
Tableau 0.30 pins `mdex ~> 0.11.1`, and MDEx 0.11 highlights inside its own NIF,
with the grammars compiled in and `:lumis` as a required dependency. Pinning a
newer MDEx yourself does not work — `mdex ~> 0.14` and `tableau ~> 0.30` have no
solution.

That is the opposite of what a project calling
[`Lumis.highlight/2`](/usage/elixir) needs, where each language is its own Hex
package. When Tableau moves to MDEx 0.14, this page moves with it: MDEx takes
`:lumis` as optional from 0.13, and `mdex_native` reads `lumis_wasm_*` packages
from 0.2.9. [NimblePublisher](/integrations/nimble-publisher) is already there,
since it leaves the MDEx version to you.

## Configure Tableau to use Lumis

```elixir
# config/config.exs
import Config

config :tableau, :config,
  url: "http://localhost:8080",
  markdown: [
    mdex: [
      extension: [
        table: true,
        header_ids: "",
        tasklist: true,
        strikethrough: true,
        autolink: true,
        alerts: true,
        footnotes: true
      ],
      render: [unsafe: true],
      syntax_highlight: [
        formatter: {:html_inline, theme: "catppuccin_latte"}
      ]
    ]
  ]
```

With that in place, fenced code blocks rendered by Tableau's Markdown pipeline will use Lumis.

## Multi-theme output

```elixir
config :tableau, :config,
  url: "http://localhost:8080",
  markdown: [
    mdex: [
      syntax_highlight: [
        formatter:
          {:html_multi_themes,
           themes: [
             light: "catppuccin_latte",
             dark: "catppuccin_frappe"
           ],
           default_theme: "light-dark()"}
      ]
    ]
  ]
```

This is the better default when your site already supports light and dark themes.
